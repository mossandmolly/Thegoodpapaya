📋 Parser Rules

  • columnsorder_date · customer_name · item_name · description · quantity · final_quantity(blank) · status(blank) · sales_order
  • customerSociety + door only — strip Indian names. "Shalu Villa 54"→"Villa 54", "Femina Iksha G1301"→"Iksha G1301"
  • sales orderDate + name no spaces. e.g. 2026-06-26-Villa54
  • item nameBase fruit from canonical list only, no qualifiers
  • descriptionALL qualifiers + delivery notes + conditions + piece count. e.g. "ripe, 3 pieces", "door pe rakh dena", "only if sweet", "ready to eat, 2 pieces"
  • piecesAlways include "N pieces" in description when order is by count
  • qty: g/kgConvert to decimal — 500g=0.5, half kg=0.5, 1/2kg=0.5
  • qty: piecesN × kg/pc from table → quantity in kg. Add "N pieces" to description
  • qty: unknownNo conversion → keep raw count as qty, flag, add "N pieces" to description
  • qty: noneNo quantity stated → use 1, flag
  • ignore👍 reacted messages, payment messages, deleted messages, system messages
  • keepComplaints, delivery notes, conditions → description field
  • societiesAuto-detected — no list needed

Config changes on this tab apply immediately to the next parse. Resets on page refresh.

          Communities are also added automatically as new orders come in — this list is for filling in each one's coordinates and trip grouping, plus adding/renaming/removing entries by hand. Combinable group is a plain label you choose — any communities sharing the same label become one trip together; leave it blank to let a community be its own single-community trip. Renaming one only fixes this record — if new orders keep deriving the old name from a customer's address, that name will just get auto-recreated alongside it, so renaming is best used for one-off typo fixes, not an ongoing display name.
